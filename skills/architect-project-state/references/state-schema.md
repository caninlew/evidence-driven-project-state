# Project-state schema

Use compact Markdown tables. Add fields only when the project requires them; do not remove the fields that protect provenance or responsibility.

## Source register

| Source ID | File | Source date | Attribution | Authority domain | Status | Locator format | Notes |
|---|---|---|---|---|---|---|---|

Authority-domain examples: statutory/regulatory, contractual, client/brief, discipline/professional, operational/user, Agent-generated. Status examples: issued, client-approved, confirmed record, provided-unverified, unconfirmed record, individual statement, Agent-generated. Never infer either dimension from filename alone.

## State register

| State ID | Class | Source observation | Current project status | Source + locator | Authority domain + status | Attribution | Effective status | Replaces | Review needed |
|---|---|---|---|---|---|---|---|---|---|

Status examples: confirmed, unconfirmed, proposed modification, provisional, contradicted, superseded, blocked.

## Metric-definition register

| Metric ID | Name | Value | Unit | Included scope | Excluded scope | Basis/date | Source | Compatible with |
|---|---|---:|---|---|---|---|---|---|

Do not compare metrics until unit and scope compatibility are established.

## Change log

| Change ID | Operation | State ID | Previous | Proposed/new | Trigger source | Authority domain + status | Effective status | Impact | Confirmation needed |
|---|---|---|---|---|---|---|---|---|---|

## Open questions

| Question ID | Question | Why it matters | Needed evidence/person | Blocks | Priority | Status |
|---|---|---|---|---|---|---|

## Proposal register

| Proposal ID | Proposal | Generated by | Rationale | Evidence | Trade-offs | Approval owner | Status |
|---|---|---|---|---|---|---|---|

Keep design ideas and Agent recommendations here until approved. Do not place them in confirmed project state.

## Bounded task pool

| Task ID | Status | Trigger/source | Objective | Inputs | Output/path | Owner | Reviewer | Completion test | Blocker/stop | Deadline status | Confirmation |
|---|---|---|---|---|---|---|---|---|---|---|---|

Allowed task status:

- `DRAFT` — missing authority, owner, input, output, or completion test.
- `READY` — authorized and executable.
- `IN_PROGRESS` — owner has begun work.
- `BLOCKED` — stop condition reached.
- `REVIEW` — output exists and awaits review.
- `DONE` — completion test passed and required reviewer accepted it.

## Version header

Record:

- project name;
- version ID;
- generated date;
- predecessor version;
- included source IDs;
- confirmation cut-off;
- authoring agent or person;
- status: draft, internal review, client review, or confirmed baseline.
