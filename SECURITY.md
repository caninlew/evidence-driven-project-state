# Security Policy

## Scope

This repository is documentation- and skill-oriented. The main security concerns are:

- accidental publication of sensitive project material;
- leakage of internal paths, personal data, names, credentials, or copyrighted source content in examples;
- instructions that grant agents excessive filesystem, network, or automation authority;
- prompt or source content that attempts to bypass project boundaries.

## Please do not submit

- client-confidential documents or private project files;
- API keys, tokens, cookies, internal URLs, or personal contact details;
- screenshots or exports containing sensitive metadata;
- proprietary source material without permission;
- examples that identify a person, practice, client, or live project when an anonymous regression case is sufficient;
- named-person or named-project research examples unless the contributor confirms necessity, permission, and source licensing.

## Private disclosure

Use GitHub Private Vulnerability Reporting from the repository **Security** tab when it is enabled. If it is unavailable, open a minimal public issue asking the maintainer for a private contact channel; do not include secrets, exploit details, or confidential data in that issue.

Relevant reports include committed secrets, confidential examples, unsafe permission guidance, or a Skill instruction that can cause unintended access or destructive action.

## Publishing rule

Assume every repository file, issue, CI log, fixture, and release artifact may become public. Review paths, metadata, attribution, licensing, and permissions before publishing.
