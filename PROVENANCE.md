# Provenance

## Origin

The repository was distilled from iterative architecture workflows in which an Agent had to separate source observations, project facts, decisions, derivations, assumptions, proposals, conflicts, and bounded next actions. Human corrections and failed baselines were used to revise the procedures before public packaging.

The public alpha was then rewritten as a de-identified, architecture-first package with portable Skill metadata, public-safe fixtures, and explicit approval boundaries.

## Public transformation

The public package applies the following transformations:

1. remove client files, confidential records, copyrighted source collections, local paths, credentials, and project deliverables;
2. remove named-person and named-practice cases from reusable Skill instructions and regression fixtures;
3. replace private cases with synthetic or abstract development fixtures;
4. preserve method logic, failure conditions, source authority, and human decision gates;
5. distinguish originating tests from compatibility targets and unverified hosts.

## Traceability of releases

Git commits and versioned releases are the public provenance record. Each empirical report should additionally record:

- repository version and commit SHA;
- Skill folder hashes or archived release DOI;
- host, model, date, tool inventory, and permission boundary;
- input and output hashes where redistribution is permitted;
- reviewer identity or review protocol;
- deviations, failures, and exclusions.

Release metadata will record a repository URL, contributor identity, and persistent identifier once those values are confirmed. Do not infer institutional authorship from contributor affiliation; see [AUTHORS.md](AUTHORS.md).
